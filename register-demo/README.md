# register-demo · 注册系统与"学习版注册机"

> 本地沙盒教学模块：一个模拟"GitHub 风格"的注册服务 + 一个学习版自动注册客户端。
> 服务只跑在 `127.0.0.1`，数据在内存里，**不与任何真实网站通信**。

## 为什么有这个模块

上一个模块（`keygens/`）教你"生成能通过验证的注册码"；
这个模块教你反过来看：**注册系统是怎么做验证的**，以及
"自动注册工具（注册机）"的代码是怎么写的——但对象是你自己搭的沙盒，不是真实网站。

## 结构

```
register-demo/
├── server.py     # 沙盒注册服务（模拟验证码/用户名校验/密码强度/邮箱验证/限流/防爆破）
├── registrar.py  # 学习版注册机（自动注册客户端）
└── tests/        # 自动化测试
```

## 快速开始

```powershell
# 终端 1：启动沙盒服务
python register-demo/server.py

# 终端 2：跑学习版注册机，注册 2 个账号
python register-demo/registrar.py --count 2
```

预期输出类似：


## 沙盒服务模拟了哪些真实机制

| 环节 | 沙盒实现 | 真实世界的对应物 |
|------|----------|------------------|
| 图形验证码 | 数学题（2 分钟过期、一次性） | reCAPTCHA / 滑块 / 点选 |
| 用户名校验 | 3-20 位字母数字横线 + 唯一性 | 各平台用户名规则 |
| 密码强度 | ≥8 位含大小写和数字 | zxcvbn 等强度评估 |
| 密码存储 | PBKDF2 加盐哈希 | bcrypt / scrypt / argon2 |
| 邮箱验证 | 6 位码（10 分钟过期、一次性） | 邮件验证链接 / 验证码 |
| 限流 | 每 IP 每分钟 5 次注册 | 反自动化风控 |
| 防爆破 | 连续失败 5 次锁 10 分钟 | 账号锁定策略 |

## 学习版注册机体现了哪些"注册机"技能

1. 自动获取验证码并解题（真实场景 = OCR / 打码平台）
2. 自动生成资料、提交表单、解析响应
3. 处理各种校验错误与 429 限流（指数退避）
4. 把"登录邮箱取验证码"抽象成一次 API 调用

## 运行测试

```powershell
python -m unittest discover -s register-demo/tests -v
```

## 为什么不能直接拿去注册真实账号

真实网站（GitHub 等）在沙盒这些机制之上还有：

- 真人检测（reCAPTCHA v3、行为分析、浏览器指纹）
- IP 信誉（机房 IP / 代理池直接拦截）
- 邮箱域名信誉（临时邮箱、黑名单域名直接拒绝）
- 账号存活检测（注册后无人使用会被判定为僵尸号封禁）

批量自动注册真实账号违反平台服务条款，也属于滥用行为。
本模块的全部价值在于：**用沙盒学会这套机制的原理和代码写法**。
